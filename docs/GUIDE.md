# SEO Статистика — подробное руководство

Self-hosted сервис SEO-аналитики: собирает данные из Google Search Console,
Яндекс.Вебмастера и Яндекс.Метрики в собственную базу, а также умеет парсить
выдачу через arsenkin и тянуть каталог доноров Miralinks. Все отчёты — со своей
историей (живёт дольше, чем API источников) и с выгрузкой в Excel/CSV.

> Этот документ — про **работу с сервисом** (источники, страницы, скрипты, API,
> эксплуатация). Установка/деплой на сервер — в [DEPLOY.md](../DEPLOY.md),
> краткий обзор — в [README.md](../README.md).

## Как устроено

- **Стек:** Python 3.11+, FastAPI, SQLAlchemy + SQLite (переключается на
  PostgreSQL через `DATABASE_URL`), APScheduler (автосбор), pandas + openpyxl
  (расчёты/экспорт), Jinja2 + Chart.js (интерфейс).
- **Принцип хранения:** данные пишутся **дневными снимками** (минимальная
  единица, которую отдают API). Любой период считается на лету
  (`WHERE date BETWEEN …` + агрегация). Это даёт сравнение периодов и экспорт за
  произвольный диапазон, а уникальные ключи делают повторный сбор идемпотентным
  (перезапись, без дублей).
- **Один пользователь, self-hosted.** Отдельной авторизации нет — закрывайте
  доступ на уровне nginx (см. DEPLOY.md), особенно если вводите ключи через UI.
- **Ключевые таблицы БД:**
  | Таблица | Что хранит |
  |---|---|
  | `site_total_daily` | итоги сайта по дням (клики/показы/CTR/позиция) |
  | `page_metric_daily` | метрики по странице по дням |
  | `query_metric_daily` | срез **запрос × страница × день** (основа TOP-1, ключей, каннибализации) |
  | `device_metric_daily` | метрики по странице **по устройствам** (десктоп/моб/планшет) |
  | `indexed_url_snapshot` | снимки страниц в индексе по датам |
  | `visit` / `hit` | визиты и хиты Яндекс.Метрики (Logs API / загрузка) |
  | `serp_result` | выдача arsenkin: строка на (запрос, ПС, регион, позиция, дата) + сниппет |
  | `serp_task` | id задач arsenkin для докачки после обрыва |
  | `donor_site` | каталог доноров Miralinks |
  | `project` / `project_url` / `url_brand` | проекты (списки URL), бренды |
  | `app_setting` | настройки/секреты (шифруются ключом `SECRET_KEY`) |
  | `collection_run` | журнал сбора (драйвер инкрементальной докачки) |

## Источники данных и подключение

Всё подключается на странице **Настройки** (`/admin`); секреты хранятся в БД
зашифрованными. Альтернатива — переменные `.env` (см. ниже).

### Google Search Console (GSC)
Клики, показы, CTR, позиция — по сайту, страницам, **запрос×страница** и по
устройствам. Два способа:
- **OAuth (проще):** Настройки → «Войти через Google» (или вставить
  `refresh_token`). Нужен OAuth-клиент типа Web с указанным redirect URI.
- **Сервисный аккаунт:** вставить JSON-ключ. ⚠️ Email сервисного аккаунта надо
  добавить **пользователем ресурса** в Search Console, иначе API вернёт **403**.

Сервис сам находит доступные ресурсы и грузит историю в фоне. Учтите **задержку
GSC ~2–3 дня**: свежие дни приходят неполными и потом уточняются (поэтому сбор
перезабирает последние дни).

### Яндекс.Вебмастер
OAuth-токен вида `y0_…` (Настройки → «Подключить Яндекс»). Сервис находит ваши
хосты и тянет клики/показы/CTR/позицию: по сайту, страницам, устройствам и
по запросам (на запрос отдаётся одна «популярная» страница), плюс снимки
страниц в индексе.

### Яндекс.Метрика
Визиты и хиты через **Logs API** (скрипт `scripts/metrika_logs.py`, нужен тот же
токен Яндекса со scope `metrika:read`) — см. DEPLOY.md, раздел «Метрика». Также
можно **загрузить выгрузку визитов файлом** на странице Метрика.

### arsenkin.tools (парсинг ТОП-10 выдачи)
API-токен из кабинета arsenkin (Настройки → ARSENKIN). Инструмент `check-top`
снимает ТОП выдачи по списку фраз в Яндексе и Google, со сниппетами. Соблюдаются
лимиты API: ≤5 задач одновременно, ≤30 запросов/мин, авто-ретрай на 429.

### Miralinks (каталог доноров для гостевых постов)
У Miralinks нет публичного API, поэтому каталог тянется **вашей сессией**:
в Настройках → Miralinks вставляются **cookie** и **тело запроса** каталога
(снимаются из DevTools, см. подсказку на странице). Сервис проигрывает запрос
постранично. Когда cookie протухает — сбор покажет понятную ошибку.

## Сбор и хранение данных

- **Автосбор:** APScheduler раз в сутки (час — `COLLECT_CRON_HOUR`, по умолчанию
  4:00). Для каждого включённого сайта берётся инкрементальное окно
  `[последняя успешная дата+1 … вчера]`, при этом **последние
  `COLLECT_REFETCH_DAYS` дней перезабираются** (GSC правит свежие данные).
  Включается флагом `ENABLE_SCHEDULER`.
- **За один сбор** по сайту тянется: итоги сайта, метрики страниц, срез
  запрос×страница (TOP-1 и ключи), метрики по устройствам, и (Яндекс) снимок
  индекса. Запись идемпотентная (upsert), повторный сбор не плодит дубли.
- **Backfill (история):** кнопка в Настройках у сайта или
  `POST /api/admin/backfill` — догрузка до ~480 дней чанками, от свежего к
  старому.
- **Ручной разовый сбор:** `scripts/run_collect_once.py --days 30`.

## Страницы интерфейса

Меню сверху. Почти везде есть выбор **домена** и **источника** (ПС), периода и
кнопки выгрузки. На страницах с большими таблицами на экране показывается
ограниченное число строк (обычно 500/1000–2000), а **в выгрузку попадает всё** —
это указано в шапке («найдено N, показано M»).

### Дашборд (`/`)
Сводка по выбранному домену: KPI (клики/показы/CTR/позиция), график динамики
(день/неделя/месяц), выбор источника(ов), кнопка запуска сбора. Переключатели:
**«чистые» данные** (за вычетом подозрительного трафика — см. Антинакрутку) и
разрез по устройствам.

### Проекты (`/upload`) и страница проекта (`/projects/{id}`)
Проект — сохранённый **список URL** (вставкой или файлом). На странице проекта:
- **ТОП-1 запрос** для каждого URL;
- **CTR** по страницам; **итоги** по подмножеству и по сайту;
- графики и **экспорт**;
- **бренды:** загрузка CSV «URL→бренд», чтобы фильтровать проект по бренду;
- **избранные цели Метрики** для проекта;
- **сравнение проекта** между периодами (`/projects/{id}/compare`).

### Сравнение (`/compare`)
Рост/падение между **периодом A и B**. Параметры: метрика
(клики/показы/CTR/позиция), группировка (**сайт / подмножество / страницы /
запросы**), `min_impressions` (отсечь шум), исключение ботов. На выходе —
топ-растущие/падающие + диаграмма. Для позиции «лучше» = меньше, направление
инвертируется.

### Антинакрутка (`/antifraud`)
Выявление подозрительных кликов по аномалиям в разрезе устройств. Параметры:
`ratio` (порог аномалии), `min_impr` (минимум показов), «объединить
свойства одного домена». Показывает страницы-подозреваемые; «чистые» итоги этой
логики используются и на дашборде/в сравнении.

### Индексация (`/indexing`)
Снимки страниц в поисковом индексе (Яндекс) с историей и **проверка списка URL**:
какие из них в индексе, какие выпали; сравнение снимков (вошло/выпало);
выгрузка совпавших URL (txt/csv).

### Метрика (`/metrika`)
Сводка по визитам Яндекс.Метрики выбранного домена и **загрузка выгрузки визитов
файлом**. Массовая закачка визитов/хитов — через `scripts/metrika_logs.py`
(Logs API), см. DEPLOY.md. Данные Метрики привязаны к домену (а не к свойству
GSC/Я.Вебмастера).

### Ключевые слова (`/keywords`)
**Все запросы**, по которым люди приходили на сайт(ы), за период: клики, показы,
CTR, средняя позиция. Фильтры: домен, источники, мин. кликов/показов, поиск по
фразе. Экспорт всех строк.

### Страницы (`/pages`)
Пер-страничный отчёт **десктоп/мобайл** с динамикой:
- клики, показы, CTR отдельно для 💻 десктопа и 📱 мобайла + «Итого»;
- главное число — текущий период; в скобке «было» — предыдущий; цветная дельта
  (рост/падение). **Период B берётся автоматически** как предыдущий равный
  отрезок (меняешь A — B сдвигается);
- выбор **домена** и **источника** (по одному, чтобы не задваивать устройства);
- поиск по URL, «Показов ≥», сортировка (текущие клики / рост / падение /
  показы);
- блок **«Свои страницы»** — вставить/загрузить список URL, чтобы смотреть только
  их (URL матчатся без учёта http/https, www, слеша);
- выгрузка Excel/CSV.

### ТОП-10 выдачи (`/serp`)
Два режима: **запуск парсинга** (через arsenkin) и **работа с уже собранной
выдачей** (из базы).

**Запуск проверки ТОП-10:**
- источник фраз: ключи из статистики по домену, **свои фразы** (текстом/файлом) —
  они приоритетнее;
- поисковики: Яндекс / Google (+ моб.);
- **регион:** выбрать город (подставит оба ID — Яндекса и Google) или вписать
  вручную;
- **глубина**, **«Фраз в задаче»** (лимит arsenkin 5000), **сниппеты**;
- идёт в фоне, прогресс виден; лимиты API соблюдаются автоматически.
- **«Догрузить недостающие (N)»** — если прогон оборвался (рестарт/сеть), задачи
  уже посчитаны на arsenkin: одна кнопка дотянет результаты без повторной оплаты.

**Результаты (из базы):**
- выбор среза (даты), «свой домен», поиск по фразе, ПС, **«Поз. ≤»** (поставь 3 —
  получишь топ-3 по каждой ПС);
- сводка **«Свои позиции в выдаче»** (в скольких фразах домен в топ-3/топ-10, ср.
  позиция);
- блок **«Топ по ключам ваших ссылок»** — вставить список URL: возьмём ключевые
  запросы именно этих страниц **из нашей базы** и покажем по ним уже сохранённую
  выдачу (arsenkin повторно НЕ запускается); вместе с «Поз. ≤ 3» это и есть
  «топ-3 со сниппетами по ключам этих ссылок»;
- выгрузка со сниппетами.

### Каннибализация (`/cannibalization`)
Где несколько ваших страниц конкурируют за один запрос:
- **по GSC** (`query_metric_daily`): запросы, где ≥2 страниц получали показы;
  показывает основную страницу и «каннибалов» (клики/показы/позиция), «в топ-10
  ≥2» и **нестабильность** (по скольким страницам Google гонял запрос по дням);
- **по выдаче** (arsenkin): фразы, где ≥2 ваших URL в живом ТОПе (оба ПС) — как
  прямое подтверждение;
- фильтры порогов, **исключение главной** (она ранжируется почти по всему);
  выгрузка.

### Доноры (`/donors`)
Каталог Miralinks для гостевых постов: фильтры (ИКС, Ahrefs DR, трафик, цена,
регион, тематика), сортировка, выгрузка. Кнопка **«Обновить базу»** тянет каталог
вашей сессией (cookie+запрос из Настроек) постранично, с паузой; апсертит по id
площадки (без дублей).

### Ошибки 404 (`/errors`)
Аналитика страниц, отдающих 404 (по визитам Метрики и маркерам): обзор по
доменам (последний период vs предыдущий) и детально по домену; список маркеров
404 настраивается.

### Настройки (`/admin`)
Подключение источников (GSC / Яндекс / arsenkin / Miralinks), управление сайтами
(добавить, включить/выключить, «Собрать», «Backfill»), выгрузка по всем сайтам за
весь период, журнал сбора, текущая конфигурация.

## Выгрузки

- Везде есть **Excel (.xlsx)** и **CSV (UTF-8 с BOM)** — открываются в Excel без
  плясок с кодировкой.
- На экране число строк ограничено для скорости; **экспорт не ограничен** —
  забирает всё под текущие фильтры.
- Лимит размера **загружаемых** файлов/полей — `MAX_UPLOAD_MB` (по умолчанию
  64 МБ); на сервере ещё нужен `client_max_body_size` в nginx (см. DEPLOY.md).

## REST API

Базовый префикс — `/api` (плюс `ROOT_PATH`, если задан). Интерактивная
документация: `/docs`.

- **Проекты:** `POST /api/projects`, `GET /api/projects`,
  `GET /api/projects/{id}`, `POST /api/projects/{id}/urls`,
  `GET /api/projects/{id}/top-keywords`, `…/ctr`, `…/compare`.
- **Метрики:** `GET /api/sites`, `GET /api/totals`, `GET /api/compare`.
- **Экспорт:** `GET /api/export`, `GET /api/export-all`.
- **Админ:** `POST /api/admin/collect/run`, `POST /api/admin/backfill`,
  `GET /api/admin/status`, `POST /api/admin/sites`.

(Страницы интерфейса и формы — отдельные маршруты `/<page>` и `/ui/...`, не
входят в `/api`.)

## Настройки (.env)

Полный список — в `.env.example`. Основное:

| Переменная | Назначение |
|---|---|
| `SECRET_KEY` | ключ шифрования секретов в БД — задайте длинную случайную строку |
| `DATABASE_URL` | `sqlite:///./data/seo.db` или `postgresql+psycopg://…` |
| `ROOT_PATH` | префикс для работы под подпутём, напр. `/stat` (пусто — корень/поддомен) |
| `PUBLIC_BASE_URL` | публичный URL для OAuth-редиректов (иначе берётся из запроса) |
| `MAX_UPLOAD_MB` | максимум на загружаемый файл/поле (по умолч. 64) |
| `GSC_AUTH_MODE` | `service_account` или `oauth` |
| `GSC_SERVICE_ACCOUNT_FILE` / `GSC_OAUTH_*` | ключ/учётка GSC |
| `GSC_SITE_URL`, `GSC_DATA_DELAY_DAYS` | ресурс GSC и задержка данных (≈3) |
| `YANDEX_WM_OAUTH_TOKEN` и пр. | Яндекс.Вебмастер |
| `YANDEX_METRIKA_OAUTH_TOKEN`, `…_COUNTER_ID` | Яндекс.Метрика |
| `ENABLE_SCHEDULER`, `COLLECT_CRON_HOUR`, `COLLECT_REFETCH_DAYS` | автосбор |
| `TIMEZONE` | часовой пояс (по умолч. `Europe/Moscow`) |

Большинство ключей удобнее задавать **через `/admin`** (хранятся зашифрованными,
без правки `.env` и рестарта).

## Эксплуатация и устранение неполадок

**Обновление версии (на сервере):**
```bash
cd /opt/seostat && git pull && .venv/bin/pip install -r requirements.txt
systemctl restart seostat
```
⚠️ Команды через `&&` обрываются при ошибке — если `cd` в неверную папку выдал
`No such file or directory`, `git pull` не выполнится. Проверьте путь
(`/opt/seostat`).

**502 после рестарта** — бэкенд не поднялся. Диагностика:
```bash
systemctl status seostat --no-pager
journalctl -u seostat -n 60 --no-pager      # тут будет трассировка
cd /opt/seostat && .venv/bin/python -c "import app.main"   # быстрый тест импорта
```
Срочно вернуть сайт: `git reset --hard <прошлый рабочий коммит> && systemctl
restart seostat`, потом разобраться по логам.

**Прогон ТОП-10 (arsenkin) оборвался** — задачи досчитаны на arsenkin, а наш
сборщик не успел их забрать:
- проще всего — кнопка **«Догрузить недостающие»** на `/serp` (для прогонов,
  запущенных после обновления, где id сохранены в `serp_task`);
- по id из кабинета arsenkin:
  `scripts/arsenkin_top.py --fetch "30355434,30355435,…"`;
- или одним махом всё незавершённое из базы: `scripts/arsenkin_top.py
  --fetch-pending`.

**Cookie Miralinks протух** — на `/donors` сбор покажет «Сессия Miralinks
недействительна — обновите cookie»: вставьте свежий cookie (и при смене фильтра —
свежее тело запроса) в Настройки → Miralinks.

**GSC возвращает 403** — email сервисного аккаунта не добавлен пользователем
ресурса в Search Console (или нет доступа у OAuth-аккаунта).

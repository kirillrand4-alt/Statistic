# Документация: Система спек-матчинга каталога против конкурентов

Матчер — вторая ступень после парсера. Парсер собирает карточки 6 сайтов в CSV;
матчер сцепляет с ними наш каталог (prokompressor.ru / Битрикс) по техническим
характеристикам и выдаёт по-брендовые Excel-отчёты со сравнением цен.

---

## 1. Назначение и архитектура

Система берёт наш каталог из Битрикса и выгрузки парсера по 6 конкурентам, для
каждого нашего товара находит тождественные карточки конкурентов (бренд + серия +
характеристики совпали в пределах допуска), и собирает по одному xlsx на бренд с
ценами всех сайтов, GAP-анализом и листами ручной проверки.

```
┌──────────────────────────────────────────────────────────────┐
│  ВХОД                                                          │
│  ┌────────────────────────┐   ┌──────────────────────────┐   │
│  │ Наш каталог (Битрикс)  │   │ CSV парсера (6 сайтов):  │   │
│  │ specs_compact.csv +    │   │ name, specs(JSON), price,│   │
│  │ products_export (цены) │   │ sku, series_status …     │   │
│  └───────────┬────────────┘   └────────────┬─────────────┘   │
└──────────────┼─────────────────────────────┼─────────────────┘
               ▼                              ▼
        load_ours_all()                load_comp_all()
               │                              │
               └───────────────┬──────────────┘
                               ▼
        ┌──────────────────────────────────────────────┐
        │  СЦЕПКА (на каждый наш товар)                 │
        │  бренд → серия+номер (обязательно)            │
        │  → match(): кВт 6% / бар 3% / произв 4%       │
        │  → ip / cool / ff / receiver-фильтры          │
        │  → раскладка: 1 = матч, 2-3 = неоднозначно    │
        └──────────────────────┬───────────────────────┘
                               ▼
        ┌──────────────────────────────────────────────┐
        │  ВЫХОД: brand_reports/<Бренд>_spec_review.xlsx│
        │  6 листов → Brands_spec_match.zip (≈51 бренд) │
        └──────────────────────────────────────────────┘
```

### Принцип
Не доверяем названиям «в лоб» (каждый сайт пишет по-своему) и ценам без проверки.
Сцепка строится на **инварианте товара**: бренд + серия+номер из названия
(обязательно), дальше характеристики должны **не противоречить** в пределах
инженерного допуска, плюс жёсткие флаги-варианты (осушитель, частотник, ресивер,
IP, охлаждение, привод).

### Модули
| Файл | Роль |
|---|---|
| `brand_spec_review.py` | главный сборщик отчётов (загрузка, сцепка, Excel) |
| `spec_match.py` | ядро сравнения: серия Atlas, допуски, флаги, фильтры, `match()` |
| `matcher.py` | распознавание бренда (`BRAND_ALIASES`, `brand_of`) |
| `power_only.py` | матчинг товаров без серии в названии (Airpol/ZUV/MIG) |
| `atlas_need_specs.py` | загрузка вселенной URL + списки на дочистку парсером |

## 2. Источники данных

| Источник | Файл | Что берём |
|---|---|---|
| Наш каталог | `specs_compact.csv` (Битрикс, колонки `IP_PROP*`) | бренд, кВт, бар, л/мин, масло, частотник, ресивер, осушитель, привод, охлаждение, вес |
| Наши цены | `products_export_*.csv` | название, URL, цена (по коду товара) |
| Конкуренты | CSV парсера (`SCRAPE_FILES`) | `product_url, name, specs(JSON), price, sku, series_status` |
| Вселенная URL | прайс-файл + sitemap (xlsx) | полный список товарных URL (даже без специй) |

### Ключевые поля Битрикса (наш каталог)
`22553 бренд · 22562 кВт · 22573 бар · 22571 л/мин · 22583 масло · 22586 частотник ·
22564/22574 ресивер · 22565 осушитель · 22601 привод · 22669 охлаждение · 22555 вес`.

### Объединение прогонов парсера
Specs склеиваются по URL из всех выгрузок в **хронологическом** порядке — поздний
прогон переписывает ключи (характеристика снята, если присутствует хоть в одном
прогоне). Прогоны обновлённого парсера помечены (`NEW_PARSER_FILES`): если URL
пройден новым парсером, а поле всё равно пустое — сайт его не публикует, повторный
прогон не нужен. Матчер читает CSV по именам колонок, поэтому новая схема парсера
(`old_price`, `price_on_request`, `category_path`…) совместима без правок.

## 3. Распознавание бренда (`matcher.py`)

Иерархия источников:
1. **Из URL** (`find_brand`) — по сегментам пути ищется ключ из `BRAND_ALIASES`
   (синонимы → канон: `dgk→dalgakiran`, `ingersoll/rand→ir`, кириллица `зиф→zif`).
2. **Из названия** (`brand_from_text`) — фолбэк для сайтов без бренда в URL; длинные
   имена проверяются раньше коротких («atlas copco» раньше «atlas»).

### Особый случай `ac`
«AC» = Atlas Copco **только если** следующий токен — серия Atlas (`ac ga22`). Иначе
«AC» = air-cooled (воздушное охлаждение), не бренд.

`BRAND_ALIASES` дополняется по охвату каталога; учтены бренды-конкуренты, которых у
нас нет (Xeleron, Denair, Kaishan), и поздние добавки (mikropor, pneumatech, rotair,
ats, friulair).

## 4. Извлечение серии — ядро сцепки

Серия+номер — **обязательное** условие. Берётся из названия + последнего сегмента
URL (без домена, чтобы «aeroCOMPRESSORs» не дал ложный «compressor»).

### 4.1 Atlas — отдельный regex (`series_num`)
Жёсткий список серий (XAHS, GA, GX, ZR, ZT, SF…). **Длинные серии проверяются раньше
коротких** — иначе короткая «x» сожрала бы «xahs». Дополнительно:
- `COPCOG 200` → `COPCO G 200` (пробел после «copco»);
- суффикс **`L` = low pressure**: `G15L ≠ G15`;
- **`+`/`plus` после номера = другая модель**: `GA11 ≠ GA11+`. Плюс ловится в трёх
  позициях: приклеен к серии (`GA11+`), к числу, и отдельным словом после давления
  (v-p-k: `GA 18 10 plus` = GA18+).

### 4.2 Дженерик-серия (`gen_series`) — все приёмы «ловли»
Первое «слово (2–12 букв) + число» после чистки:

| Приём | Зачем | Пример |
|---|---|---|
| Кириллица → латиница (`_CYR2LAT`) | наш каталог пишет серии кириллицей, конкуренты латиницей | `екоcd` → `ekocd`, `ВК-18.5` → `vk18.5` |
| Склейка дефиса/точки внутри слова | разное написание | `k-max` → `kmax`, `dr.sonic` → `drsonic` |
| Сохранение десятичных | не разбить дробь | `i.18,5` → `i 18,5` (но `18.5` цело) |
| Отброс маркетинг-слов | «new/новый» — не серия | `COMARO MD NEW 55` → `MD55` |
| Стоп-слова и бренд-токены пропускаются | «винтовой/компрессор/бренд» — не серия | пропуск до реальной серии |
| Одиночная латинская буква-вариант | линейка инвертора | `GENESIS I` ≠ `GENESIS` |
| Хвост до 2 латинских токенов после числа | заводские sku (доказано V1-артикулами) | `Ozen OSC 110D/110U/110S` |
| `+` приклеенный к числу = часть имени | `HCA+ ≠ HCA` | `ARIACOM HCA+110` |
| «plus» сразу после бренда = реальная серия | не маркетинг | `Fini PLUS 11-08` |
| FALLBACK: одно-буквенная серия | только если основной проход дал None | `Atom А-11`, `Boge C 10`, `IR R110` |

### 4.3 Отбрасывание хвостов и хвостовые маркеры
- **Стоп-суффиксы** не входят в ключ серии: `plus, vsd, ff, pack, tm/fm, ac/wc`,
  единицы. Так `VEGA 11 R PLUS` и `VEGA R PLUS 11` дают один ключ.
- **Хвостовые флаги** (`suffix_flags`): `Д/D` после числа/«л» = осушитель (`270L D`);
  `ВС/bc` = воздухосборник; `/O, /OW, /O2` (Zammer) = осушитель.

### 4.4 Berg — заводская схема кодов ВК (`berg_suffix`)
Буквы в коде ВК декодируются (подтверждено пропами каталога):

| Буква | Значение |
|---|---|
| `Р` | ременный привод |
| `Е` | частотник (VSD) |
| `О` | осушитель |

Комбинации `РЕ/РО/РЕО`; буквы приклеены к числу (`ВК-18.5РО-500`) или идут одиночными
токенами после (`ВК-11 Е 10`). Схема убрала «монстров» Berg (≈16 пар на товар → ≈4.7).

## 5. Числовые характеристики и допуски (`spec_match.py`)

| Характеристика | Допуск | Почему так |
|---|---:|---|
| кВт | 6% | разброс округлений мощности двигателя |
| бар | 3% | v-p-k пишет рабочее (6.9 при номинале 7); но 7 vs 7.5 (6.7%) режем |
| производительность | 4% | `GA11=1560` vs `GA11+=1820` не путать |

**Санитарные диапазоны** (отсев мусора): кВт `0.2…2000`; бар `3…400`; цена `100 ₽…50 млн ₽`.

### 5.1 Приведение производительности к л/мин (`flow_to_lmin`)
По единице из ключа: `м³/мин ×1000`, `м³/час ÷0.06`, `л/мин` как есть; без единицы и
`<60` — трактуем как м³/мин. Отсев нереального (`<100` или `>120000` л/мин) — заодно
ловит давление, случайно попавшее в поле произв.

### 5.2 Диапазоны → максимум
У VSD произв. и давление пишут диапазоном (`575–2935 л/мин`, `4–13 бар`). Берём
**максимум** = номинал модели (как в каталоге prokompressor).

### 5.3 Сдвоенные карточки (`bar_flow_pairs`)
Карточка `8/10 бар` + `1.665/1.435 произв` = перечень вариантов на одной странице →
разбиваем на пары `(8, 1665)`, `(10, 1435)`, каждая матчит свой SKU. `/` = варианты,
` - ` = непрерывный диапазон. Цена одна → вешаем на **младший** (базовый) вариант.

### 5.4 Различение производительности и «Производителя» (`is_flow_key`)
Ключ «Производительность, л/мин» = производительность; «Производитель» /
«Производство» / «Гарантия производителя» / «Страна производства» = **нет** (все
ловятся подстрокой «произв»). Этот баг прятал произв у тысяч карточек rutector
(восстановлено ~3 380; полный паспорт `2 965 → 6 344`).

## 6. Флаги-варианты

Варианты одной серии+номер сильно влияют на цену; вшиты в артикул/название
(`text_flags`) или лежат в пропах/спеках.

| Флаг | Откуда | Примечание |
|---|---|---|
| **FF — осушитель** | имя (`G 11 10FF`), спек-ключ, проп 22565 | часто приклеен к давлению |
| **VSD — частотник** | имя (`vsd/частот/инвертор/VS/I-серии ABAC/MEI`), проп 22586, спек | **+до 35% к цене** |
| **Ресивер** | `ресивер/TM + число`, хвост `270/500/900`, проп 22564/22574 | `100/150/200/300` — только хвостовые |
| **IP-класс** (`ip_class`) | имя | `54 ≈ 55` (нормализуем 55→54), `23` — другой |
| **Охлаждение** (`cool_class`) | проп 22669, спек, имя | water/air; «оба» → None (подходит к любому) |
| **Привод** | проп 22601, спека, схема Berg | ременной/прямой |

### 6.1 Тристейт для да/нет-полей (частотник, осушитель)
Принципиально: **«нет данных» ≠ «нет»**.

| Значение | Смысл | Источник приоритета |
|---|---|---|
| `1` | знаем-да | имя-маркер > проп 22586 > спек-ключ |
| `0` | знаем-нет | проп/спека явно «нет» |
| `None` | не указано | **матчится**, но подсвечивается пометкой `⚠` |

## 7. Направленные фильтры: «молчание = совместимо»

Главный принцип — **режем кандидата только при ЯВНОМ конфликте** обеих размеченных
сторон; молчание одной стороны = не противоречие. Применяются цепочкой после `match`:

```
match → ip_filter → cool_filter → ff_filter → receiver_filter
```

| Фильтр | Поведение |
|---|---|
| `ip_filter` / `cool_filter` | отбрасываем, только если обе стороны размечены и классы различаются |
| `ff_filter` (осушитель) | если в серии конкурент размечает FF — молчуны при нашем FF отбрасываются; если FF не пишет никто (Atlas ZR/ZT) — молчание не противоречит |
| `receiver_filter` | наш артикул всегда кодирует вариант: нет ресивера у нас → явные ресиверы убираем; есть → молчунов отбрасываем при наличии явных, объёмы должны сойтись |

Частотник и привод — внутри `match`: режем только явный конфликт (`1 vs 0`); привод
сравниваем, лишь когда известен с обеих сторон.

---

## 8. Правило сцепки `match()`

Кандидат проходит, если:
1. **серия+номер совпали** (обязательно);
2. кВт ±6%, бар ±3%, произв ±4% — где значения есть с обеих сторон;
3. **частотник** не в явном конфликте (`1≠0`);
4. **привод** не в конфликте (если известен с обеих сторон);
5. **осушитель** и **ресивер** не в конфликте.

**Масло НЕ сравниваем:** внутри одной серии+номер масляность не варьируется, а
конфликт = враньё сайта (`compressortyt`: XAS97 помечен «безмасляный» на масляном).

После `match` — направленные фильтры (раздел 7). Раскладка результата:

| Кандидатов с сайта | Лист |
|---|---|
| 1 | спек-матч |
| 2–3 разных | неоднозначные (жёлтый, проверить) |
| разные исполнения одной физ-спеки (AC/WC/Pack/фаза) | сворачиваются в один товар, цена = min |

## 9. Структура выходного файла (Excel)

Один файл на бренд: `brand_reports/<Бренд>_spec_review.xlsx`, до 6 листов.

### 9.1 Листы
| Лист | Что показывает |
|---|---|
| **спек-матч** | главный: наш товар ↔ цены 6 сайтов, min, Δ%, почему сцепилось |
| **неоднозначные** | у ≥1 сайта нашлось >1 разной модели — ручная проверка |
| **GAP — нет у нас** | модели у ≥2 конкурентов, которых у нас нет (дыры ассортимента) |
| **Проверить карточку** | наша спека расходится с конкурентами той же модели (`card_issue`) |
| **Снятые у конкурентов** | карточки со статусом «снято» + наш товар того же ряда |
| **Особо проверить (нет серии)** | power-only: товары без серии в названии (Airpol/ZUV/MIG) |

### 9.2 Колонки листа «спек-матч»
`№ · Наш товар · Ваша цена · [compressortyt · aerocompressors · pnevmoteh ·
pnevmo-sklad · v-p-k · rutector] · min конк. · Δ к min, % · Почему сцепилось ·
Проверить карточку · ВЕРДИКТ`.

### 9.3 Цвета и шрифты ячеек
| Оформление | Значение |
|---|---|
| Синий подчёркнутый (`0563C1`) | гиперссылка / активная цена |
| Красный зачёркнутый (`C00000`) | снято с производства |
| Жёлтая заливка (`FFE699`) | свёрнуто несколько карточек/исполнений — проверить |
| Светло-серая заливка (`F2F2F2`) | с этого сайта матча нет |
| Оранжевый (`C55A11`) | спека под вопросом (ВЕРДИКТ / `card_issue`) |
| Персиковая заливка (`FCE4D6`) | наш товар, у которого спека под вопросом |
| Бел. жирный на тёмно-синем (`305496`) | шапка |
| Текст `По запросу` | цена не найдена (есть карточка, нет цены) |
| Текст `снято` | снято с производства, цены нет |

### 9.4 Колонка «Почему сцепилось»
Расшифровка матча одной строкой:
```
GA22 · кВт 22≈22 · бар 8≈8 · произв 3800≈3750 · FF · VSD · ресивер 500≈500 · возд.охл · ⚠ VSD у конкурента не подтверждён
```
- `СЕРИЯ+НОМЕР` заглавными; `кВт/бар/произв X≈Y` — наше ≈ конкурента (`—` если нет);
- `FF`/`VSD` — активные флаги; `ресивер X≈Y`; `вод.охл`/`возд.охл`;
- **`⚠`** — особая пометка тристейта: одна сторона ДА, вторая молчит (риск +35% к
  цене). «Знаем-нет ↔ молчит» не шумим.

Колонка **ВЕРДИКТ** дублирует `card_issue` в строке матча (оранжевым, ссылкой на
сайт-источник), если наша спека расходится с конкурентами.

## 10. Алгоритм полного прогона

```
1. Запуск: python brand_spec_review.py [бренд ...]
2. load_ours_all()  — наш каталог: бренд → серия → флаги → кВт/бар/произв + цена
3. load_comp_all()  — карточки конкурентов: то же + статус/цена/sku из CSV парсера
4. build_po_pairs() — power-only пары (товары без серии)
5. Для каждого бренда:
   a. сгруппировать кандидатов по серии+номеру
   b. для каждого нашего товара: match() → ip/cool/ff/receiver-фильтры
   c. свернуть исполнения (AC/WC/фаза), выбрать цену = min
   d. разложить: 1 = спек-матч, 2-3 = неоднозначные, 0 = нет матча
   e. собрать листы GAP / Проверить карточку / Снятые / Особо проверить
   f. записать <Бренд>_spec_review.xlsx
6. Упаковать всё в Brands_spec_match.zip
```

## 11. Запуск и вспомогательные инструменты

```bash
python brand_spec_review.py            # все бренды → brand_reports/ + Brands_spec_match.zip
python brand_spec_review.py atlas      # один бренд (отладка)
python power_only.py airpol zuv mig    # пилот power-only с детектором ложных срабатываний
```

Печатает по каждому бренду сводку: `матч / неодн / без / GAP / карточки / снятые /
без серии`.

| Скрипт | Назначение |
|---|---|
| `atlas_need_specs.py` / `brands_need_specs.py` | списки URL без полного паспорта (кВт+бар+произв) на дочистку парсером |
| `categories_need_scan.py` | осушители/ресиверы/азот на сканирование (с фильтром серий/диапазонов) |
| `category_spec_review.py`, `dropped_export.py`, `unmatched_export.py`, `match_validation.py` | срезы и валидация |

## 12. Требования

```
Python 3.10+
openpyxl       (запись xlsx)
```

Матчер работает на стандартной библиотеке + `openpyxl`; на вход берёт CSV парсера и
выгрузки Битрикса, внешней сети не требует.
